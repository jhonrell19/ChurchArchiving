# Staging acceptance checklist

Apply `deploy/migrations/20261128_certificate_workflow.sql` to **staging** before deploying either service. It adds four private tables and a status trigger. Historical requests retain their original fields. History begins with the first transition following migration. Run as the application database owner or grant the runtime role the necessary table and sequence privileges. For a clean local PostgreSQL installation, create the Supabase roles anon and authenticated before running the migration. Deploy both the Flask and Next.js commits together. Use only fictional parish records in this checklist.

## Staging configuration

- For Gmail delivery over HTTPS set `EMAIL_TRANSPORT=gmail-api` on **ifimarag**. Enable Gmail API on the sending mailbox's Google Cloud project. Use a confidential OAuth client authorized by that mailbox with offline access and only `https://www.googleapis.com/auth/gmail.send`. Set `GMAIL_SEND_CLIENT_ID`, `GMAIL_SEND_CLIENT_SECRET` and `GMAIL_SEND_REFRESH_TOKEN` privately in Render. Set `APP_BASE_URL=https://ifimarag.onrender.com`. Existing verified-domain Resend configuration is also supported.
- On both services match `FLASK_INTERNAL_KEY`. On the web service configure `FLASK_API_URL` and the PayMongo webhook signing secret. On the API service set the matching PayMongo test secret and public app URL. In the test merchant configure the paid checkout event to POST to `https://ifimarag.onrender.com/api/paymongo/webhook`.
- On **smart-parish-api** optional batch limits are `ARCHIVE_BATCH_FILES=20`, `ARCHIVE_BATCH_FILE_MB=10`, `ARCHIVE_BATCH_DAILY=100`, `ARCHIVE_BATCH_TYPES=pdf,jpg,jpeg,png`. Batch allowance counts successfully archived scans per staff account and Philippine calendar day. The single-file transport ceiling is 15 MB.
- Request OTP uses the verified account email. The code expires after ten minutes and each account can request a new one after one minute. Proofs up to 3 MiB are stored in the private database and served as attachments after staff role and office-scope checks. Existing church documents continue using the archive's configured storage.
